### 先に、この道具がしないことを書きます

**置いただけの状態では、文章は作りません。** 過去の質問と答弁を並べ、答弁書の定型句を数え、質問主意書の型（前提の事実・過去の答弁の引用・問い）を空欄つきで示すところまでです。

**事務所の中の AI（Ollama など）を設定すると、下書きまで作れます。** そのときも、下書きの「」の引用は渡した答弁書の原文と一字一句照合し、合わないものは出しません。提出の前に引用と事実を原文で確かめ、仕上げるのは人です。

**要約も論評もしません。** 出すのは、衆議院・参議院が公開している質問本文と答弁本文の機械的な抜粋と、原文へのリンクだけです。

**「答えていない型」は評価ではありません。** 答弁書に出てくる定型句（「お答えすることは困難である」「御質問の趣旨が必ずしも明らかではない」「承知していない」「検討してまいりたい」「仮定の御質問」「個別の事案」）を語の一致で数えたものです。

---

### 何ができるか

**論点の語を入れると、同じ論点の過去の質問・政府の答弁・答えていない型が1画面に並びます。**

1. **政府はこう答えている** … 答弁書の段落のうち検索語を含むものを、原文のまま新しい順に。要約しません
2. **答えていない型が返った質問** … 同じ聞き方をすると同じ型が返りやすい、という材料
3. **過去の質問主意書** … 件名・提出者・提出日・答弁書受領日・型のタグつき
4. **質問主意書の型** … 前提の事実／過去の答弁の引用／問い（「困難」とされた点は数字と期間を限定して聞き直す、「検討中」は主体と期限を聞く、「承知していない」は把握の予定を聞く）を空欄つきで

過去の質問の欄には、**意味の近い質問主意書**も別枠で出ます。件名と質問本文を multilingual-e5-large で数値にして、前もって近いものを計算しておいた表です。「教育費」で探したときに「学費」「授業料」の質問主意書のように、同じ言葉を使っていないものも拾えます。画面を開くときに AI は動かないので、AI の設定が無くても出ます。

### AI（LLM）を設定すると増えること

同梱の `kshuisho_config.example.php` に、事務所の中の Ollama など（OpenAI 互換の口）を書くと、次の2つが増えます。設定しなければ画面には出ず、これまでどおり外部に何も送りません。

- **言い換えで探す** … 入れた語の言い換えと関連する語を AI に出させ、その語でも探します。元の語の結果とは分けて「言い換えでも探した結果」として並べます。AI の応答が遅いときは、元の結果だけを出します
- **下書きを作る** … アシストで集めた答弁書の原文と過去の質問を、番号つきの出典として AI に渡し、件名・前提の事実・過去の答弁の引用・一〜三の問いの下書きを作ります。作ったあと、サーバーで「」の引用が原文に一字一句含まれるか、出典番号が渡したものか、前提の事実の数字が原文にあるかを確かめ、外れたら下書きを出しません。下書きは保存しません

既定のモデルは gemma4:12b（Ollama で動く、手元に置ける大きさのもの）です。デモでも当社のサーバーの gemma4 で動かしています。

あわせて、次のページが最初から入っています。

- **質問主意書1件のページ** … 質問本文と答弁本文を左右に、提出日・内閣転送日・答弁書受領日・提出からの日数・答弁の項目数つき
- **提出者ごと**、**回次ごと**、**型ごと**の一覧
- **CSV と JSON API**、**sitemap.xml・llms.txt**

### なぜ要るのか

質問主意書は月に1,600回検索されている制度で、衆参のサイトに全文が公開されています。ただし件名の一覧しかなく、本文の中は検索できません。「この論点は過去に誰が聞いて、政府は何と答えたか」を調べるには、会期ごとの一覧を開いて1件ずつ本文を読むしかありません。

秘書の調査時間はここに消えます。そして同じ聞き方をすると、同じ「お答えすることは困難である」が返ってきます。

この道具は、本文の中までことばで引けるようにして、答弁の定型句を数えただけです。それだけで、次に何を聞くべきかが見えます。

### 置き方（3分）

1. `kshuisho.php` と `kshuisho_data/` を置く
2. その階層の `.htaccess` に `AddHandler php-script .php` を書く（共有サーバーの既定がPHP5.6のことがあるため）
3. `https://あなたのドメイン/kshuisho.php/` を開く

**データベースサーバーも常駐プロセスもポートも要りません。** 必要なのはPHP 8とPDO SQLiteだけです。AI を設定しなければ書き込み権限も不要です。**検索は置いた場所で完結し、AI を設定しなければ外部のAIやAPIには何も送りません。** AI を事務所の中の Ollama にすれば、下書きを作るときも、どの論点を調べているかが外に出ません。

### 更新のしかた

会期が進むと質問主意書と答弁書が増えます。同梱のPythonを3本動かせば、新しいデータベースができます。

```
python3 scripts/fetch_shugiin.py --from 212 --to 221
python3 scripts/fetch_sangiin.py --from 212 --to 221
python3 scripts/build_db.py
python3 scripts/build_similar.py   # 意味の近い質問主意書の表（任意）
```

会期の範囲は引数で広げられます（古い回次も同じ形式で公開されています）。

### こんな方に

- **国会議員事務所** … 質問主意書を書く前に、同じ論点の過去の質問と答弁を5分で並べられます。答弁書の原文をそのまま引用できます
- **地方議員事務所** … 国が「検討中」「承知していない」と答えている論点は、地方議会で聞く材料になります
- **記者・研究者** … 「お答えすることは困難」がどの論点に集中しているかを、提出者別・回次別に数えられます
- **自治体のDX担当** … 国の公開ページを本文まで引ける形にする例として、そのまま流用できます

### 下書きの引用を原文と照合する理由

質問主意書は国会議員が議長に提出する公文書で、過去答弁の引用が1文字違えば、答弁書で「御指摘の答弁は存在しない」と返されます。生成AIは、もっともらしい答弁を作ってしまうことがあります。

そこで、下書きの中の「」で括った引用は、AI に渡した原文に一字一句含まれるかをサーバーで機械的に確かめ、1つでも合わなければ下書きそのものを出さないようにしています。引用ごとに、どの答弁書（院・回次・番号・受領日）から引いたかの番号も付きます。前提の事実に書く数字も、引いた出典の原文にあるものだけを通します。

それでも、下書きは AI が作ったものです。画面にもそう書いてあります。提出の前に、引用と事実を原文で確かめてください。

事務所の書式や、相談記録と結びつけた下書きにしたい場合は、バイブカスタマイズでお足しできます。
