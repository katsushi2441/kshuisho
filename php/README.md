# Kurage 質問主意書アシスト（kshuisho）

衆議院・参議院の**質問主意書と政府答弁書**を、件名だけでなく本文の中までことばで引ける形にしたものです。
同じ論点で過去に誰が何を聞き、政府が何と答え、どこが「お答えすることは困難」とされたかを1画面に並べます。

デモ: <https://kurage.exbridge.jp/kshuisho.php/>

**しないこと**: 要約・論評・答弁の良し悪しの判定。出すのは本文の機械的な抜粋と、定型句の一致だけです。
文章（質問主意書の下書き）は、AI（LLM）の設定をしたときだけ作ります。そのときも、引用は原文と一字一句照合し、合わないものは出しません。下書きを確かめて仕上げるのは人です。

## AI（LLM）の有無で変わること

| | 設定なし（置いただけ） | 設定あり（`kshuisho_config.php`） |
|---|---|---|
| ことばで探す・アシスト・型 | そのまま | そのまま |
| 似た質問主意書 | 出る（DB に表があれば） | 出る（DB に表があれば） |
| 言い換えで探す | 出ない | 出る |
| 下書きを作る | 出ない | 出る |
| 外部への送信 | しない | 言い換えと下書きのときだけ、設定した LLM に検索語と原文の抜粋を送る |

- **似た質問主意書**は AI を使いません。`scripts/build_similar.py` が前もって計算した表（`similar`）を読むだけです。質問主意書のページに「似た質問主意書」、アシストの「過去の質問」に「意味の近い過去の質問（ことばは一致しないもの）」が出ます。表が無い DB でもそのまま動きます。
- **言い換えで探す**: 検索とアシストで、入れた語の言い換えと関連語（最大5語）を LLM に JSON で出させ、その語でも探します。元の語の結果とは分けて「言い換えでも探した結果（○○・△△）」として出します。同じ語はキャッシュから返します。LLM の応答が無い・遅い（既定8秒）ときは、元の検索結果だけです。画面を出したあとに読み込むので、元の結果の表示は待たされません。
- **下書きを作る**: アシストの「5. 下書きを作る」。答弁の原文の段落・答えていない型が出た段落・過去の質問の冒頭を番号つきの出典として LLM に渡し、件名・前提の事実・過去の答弁の引用・一〜三の問いを作らせます。作ったあと、サーバーで次を確かめます。
  - 「」で括った文が、渡した原文のどれかに一字一句含まれるか（引用は、引いた出典番号の原文に含まれるか）
  - 出典番号が、渡したものか（引用は種類が「答弁」の出典か）
  - 前提の事実の数字が、引いた出典の原文にあるか
  1つでも外れたら1回だけ作り直し、それでも外れたら下書きを出さずに「作れませんでした」と出します。下書きは保存しません。IP ごとに1時間10回（全体で60回）まで、論点の語は3つ・40字まで。
  検査が働くことは `php scripts/test_draft_check.php`（LLM なし）と `php scripts/test_draft_check.php --llm "教育費"`（LLM で作った下書きにわざと原文に無い引用を混ぜて止まるか）で確かめられます。

### 設定のしかた

`kshuisho_config.example.php` を `kshuisho_config.php` という名前で `kshuisho.php` と同じ階層にコピーし、
OpenAI 互換の chat/completions の URL を書きます。事務所の中の Ollama なら `http://<OllamaのIP>:11434/v1` です。
既定のモデルは `gemma4:12b-it-qat`（`ollama pull gemma4:12b-it-qat`）。思考型のモデルなので、`reasoning_effort=none` を送って思考を切っています。

設定すると、`kshuisho_data/kshuisho_llm.sqlite` を PHP が作ります（言い換えのキャッシュと、回数制限のための IP アドレスと時刻。1時間で消します）。
`kshuisho_data/` に PHP が書き込めることと、`kshuisho_data/.htaccess`（直読みの禁止）が効いていることを確かめてください。

## 置き方

PHPが動くレンタルサーバーに、この3つを置くだけです。データベースサーバーも常駐プロセスも要りません。

```
kshuisho.php
kshuisho_data/kshuisho.sqlite    ← 質問本文・答弁本文
kshuisho_data/.htaccess          ← Require all denied（SQLite の直読みを止める）
images/ogp/kshuisho.png          ← OGP画像
kshuisho_config.php              ← 任意。AI（LLM）を使うときだけ（下の「AI（LLM）の有無で変わること」）
```

必要なのは **PHP 8 と PDO SQLite** だけです。heteml をお使いの場合は、置いた階層の `.htaccess` に
`AddHandler php-script .php` が要ります（無いと PHP 5.6 で動いてエラーになります）。

`kshuisho.php` の先頭にある `$SITE`（表示名）・`$OGP`（OGP画像のURL）・`$STORE` を、ご自分のサイトに合わせて書き換えてください。

## 画面

| URL | 内容 |
|---|---|
| `/` | ことばで探す（件名・質問本文・答弁本文） |
| `/search?q=語` | 検索結果（抜粋つき）。`&house=参議院` `&session=217` `&giin=浜田` `&pat=困難` `&ans=1` を重ねて絞れる。ことばが無くても絞り込みだけで引ける |
| `/assist?q=語` | **アシスト**: 同じ論点の「政府はこう答えている（原文の段落）」「答えていない型が返った質問」「過去の質問」（意味の近いもの・言い換えで当たったものも別枠で）「質問主意書の型（空欄）」、AI の設定があれば「下書きを作る」 |
| `/q/{id}` | 質問主意書1件（質問本文・答弁本文・提出日・転送日・受領日・型・似た質問主意書） |
| `/giin` `/giin/{名前}` | 提出者ごと |
| `/pattern` `/pattern/{型}` | 「答えていない型」ごとの答弁 |
| `/session/{院}/{回次}` | 回次ごと |
| `/api?q=語` `/data/questions.csv` | JSON・CSV |
| `/llms.txt` `/robots.txt` `/sitemap.xml` | AI検索・検索エンジン向け |

検索は置いた場所で完結し、AI の設定をしなければ外部のAIやAPIには何も送りません。

## データを新しくする

```bash
python3 scripts/fetch_shugiin.py --from 1 --to 221   # 衆議院（会期の範囲）
python3 scripts/fetch_sangiin.py --from 1 --to 221   # 参議院
python3 scripts/verify_raw.py --delete                # 途中で切れたファイルを消す
python3 scripts/build_db.py                           # → kshuisho_data/kshuisho.sqlite
python3 scripts/build_similar.py                      # 似た質問主意書の表を足す（任意。pip install fastembed numpy）
```

`build_db.py` は DB を作り直すので、`build_similar.py` も毎回その後に流します（流さなければ「似た質問主意書」が出ないだけです）。
`build_similar.py` は multilingual-e5-large を CPU で動かします（初回はモデルを約2GB落とします。2,167件で30分ほど）。
埋め込みは件ごとに控えておくので、2回目からは増えた分だけ計算します。

新しい会期を足すだけなら `--from` をその会期にします。全会期をはじめから落とすと、
1リクエスト1秒なので衆参それぞれ6時間ほどかかります。`scripts/backfill_all.sh` は
これを衆参で並行に流します（落としたものは取りに行かないので、途中で止めても続きから）。

- 生HTMLは `/mnt/data/kshuisho/raw/` に残します（取り直しません）。
- **衆議院はデータベースが2つに分かれています。** 第148回以降が `itdb_shitsumon.nsf`、
  第147回以前が `itdb_shitsumona.nsf`。第1回（1947年）から本文HTMLがあります。
- **会期は3桁ゼロ詰め**です（`kaiji001_l.htm`。`kaiji1_l.htm` は404）。参議院も同じ。
- 衆議院は Shift_JIS、参議院は UTF-8。参議院のサイトは User-Agent に製品名が入ると 502 を返すので、素の UA で1秒あけて取ります。
- 一覧は毎回取り直します（答弁書が後から増えるため）。

## 「答えていない型」

答弁書に現れる定型句を、語の一致で数えたものです（`build_db.py` の `EVASIVE`）。

| 型 | 語 |
|---|---|
| 困難 | お答えすることは困難／困難である |
| 趣旨不明 | 趣旨が必ずしも明らかではない／意味するところが明らかではない |
| 承知せず | 承知していない／把握していない |
| 検討中 | 検討してまいりたい／検討中である |
| 仮定 | 仮定の御質問 |
| 個別事案 | 個別の事案／個別具体的な |

**答弁の評価ではありません。** 同じ論点で過去にどの型が返ったかを、次の質問を書く前に確かめるためのものです。
